# MiniMax H3 を A100 で動かす最適構成

A100（SM80・40 GB / 80 GB）1枚で、**速度と品質の両立**を目標にした構成です。
HAYATEの既定値は RTX 3060 12 GB 向けで、DiTの50ブロック中49ブロックをCPUに退避し、
32Bテキストエンコーダを1層ずつPCIe転送しています。A100ではこの退避処理が最大の
ボトルネックになるため、**全ステージをGPUに常駐**させ、A100が得意な
**INT8 Tensor Core**を使うモデルに切り替えます。

> 注意: 以下の選定はヘッダー監査・上流実装・RTX 3060での実測に基づく設計です。
> A100実機での速度と画質は未測定です。導入後に `scripts/benchmark_a100.py` で確認してください。

## 推奨構成

| 役割 | 推奨ファイル（Comfy-Org/MiniMax-H3 @ `4cc1d817`） | サイズ | 理由 |
|---|---|---:|---|
| DiT | `minimax_h3_fl2va_pruned_int8_convrot` | 19.5 GiB | 8-bit重み（W4A8より量子化誤差が小さい）。`torch._int_mm`でINT8 Tensor Coreを使用。40 GBにも常駐できる |
| テキストエンコーダ | `qwen3vl_32b_minimax_h3_int8_convrot` | 25.3 GiB | GPU常駐。A100にはFP4演算器がなく、NVFP4では層ごとにBF16へ展開するため、INT8の方が高精度かつ高速 |
| Video VAE | `minimax_h3_video_vae_int8_convrot`（既存） | 3.0 GiB | 検証済み。Conv重みはFP32のままで、INT8は144個のLinearのみ |
| Audio VAE | `minimax_h3_audio_vae_fp32`（既存） | 0.6 GiB | 変更なし |
| 任意（80 GB） | `qwen3vl_32b_minimax_h3_bf16` | 48.0 GiB | プロンプト埋め込みを無量子化にする品質比較用 |

上流エンジンはテキストエンコーダ → VAE → DiT の順に実行し、同時にはGPUへ載せません。
そのため各段を個別に全常駐でき、40 GBでも収まります。80 GBではさらに活性化メモリに
余裕が出るため、高解像度・長尺を扱いやすくなります。

### 採用しなかったもの

- **FP8 DiT**: A100（Ampere）にはFP8演算器がなく、重み展開のコストだけがかかります。
- **BF16フルDiT（61.7 GiB）**: 80 GBに載りますが、`adaln_proj`だけで約13Bパラメータあります。
  pruned版はこれを約155 MBの曲線表現に圧縮しており、ブロック本体の精度は同じです。
- **pruned BF16 DiT（37.5 GiB）**: 無量子化の比較基準として有力です。ただし精度の異なる
  テンソルが混在するヘッダーで、HAYATEは安全側に倒して`UNKNOWN`扱いにします。対応は今後の課題です。
- **Video VAE FP16**: 上流の厳格なキー照合がComfy形式の単一ファイルに対応しているか未確認のため、見送りました。
- **Sol-Attn（`--attn_mode sol`）**: 上流に同梱された、学習不要のNVIDIA製スパースアテンションです。
  A100でも動作しますが、HAYATEでは未検証のため、比較候補にとどめています。

## プロファイル

| プロファイル | 用途 | 内容 |
|---|---|---|
| **A100 高速・高画質**（`a100_detail`） | 推奨 | 20点・SageAttention 2.2・EasyCache 0.4（15〜85%、最大2連続スキップ）。3060で検証済みの「高速・画質優先」と同じ計算手順を、全常駐＋INT8 Tensor Coreで実行 |
| **A100 品質基準**（`a100_quality`） | 比較の基準 | 50点・SDPA・キャッシュなし・INT8は重みのみの誤差（展開して計算） |
| **A100 PDD 8-Step**（`a100_pdd`） | 最速候補 | Alibaba PAI蒸留の8回評価・SDPA。範囲読みで、pruned INT8 DiTの`adaln_t_table`がW4A8版と同一（SHA-256一致）であることを確認済み |

- 3つのプロファイルはすべて、ブロック退避0・テキストエンコーダ全層常駐・VAEタイル256（512は
  3060でゴーストが出たため不採用）を使います。
- WebUIはVRAM 38 GiB以上のGPUがある場合だけA100プロファイルを表示します。サーバー側でも、
  小さいGPUへの割り当てを拒否します。大小のGPUが混在する環境では、実行GPUの明示指定が必要です。
- 上流の`--int8_fast`は、DiTとテキストエンコーダの両方をint_mm化します。HAYATEは
  テキストエンコーダを重みのみ誤差の経路に固定します。1プロンプト1回の処理で、int_mmによる
  高速化はほぼなく、埋め込みに活性化誤差が加わるだけだからです。上流と同じ動作に戻すには
  `HAYATE_TEXT_ENCODER_INT_MM=1` を設定します。
- 速度だけを最優先する場合の選択肢として、既存の **FastH3 INT8**（4ステップ、SM80以上）も
  使えます。蒸留・スパース化によって画質がどう変わるかは未比較です。

## 導入手順

1. 設定 → モデルを準備 →「A100（40/80GB）」を選び、規約を確認して未取得モデルを取得します
   （DiT 19.5 GiB＋TEXT 25.3 GiB。VAEと補助ファイルは共通）。
2. 「標準パスを適用」を押すと、モデル定義が `configs/models.a100.yaml` に切り替わります。
3. SageAttention 2.2をインストールします（Linuxでは `pip install sageattention`。SM80対応のカーネルを含みます）。
4. 生成画面で「A100 高速・高画質」を選びます。

CLIでは次のように実行します。

```bash
hayate generate --a100-detail --config configs/models.a100.yaml \
  --upstream /path/to/h3 --ckpt-dir models/minimax-h3-snapshot \
  --prompt "..." --output outputs/a100.mp4 --width 768 --height 448
```

## 実機での確認

```bash
python scripts/benchmark_a100.py --upstream /path/to/h3 --ckpt-dir models/minimax-h3-snapshot
```

同じプロンプト・Seed・解像度・尺で、次の変種を`a100_quality`と比較します。

- `a100_detail`
- SDPA版（SageAttentionの影響）
- dequant版（INT8 Tensor Coreの影響）
- キャッシュなし版（EasyCacheの影響）
- PDD 8-Step
- 旧来の3060向け配置（常駐による高速化の効果）

各変種の所要時間・VRAMピーク・SSIM/PSNRを `benchmarks/a100/report.json` に保存します。
SSIM/PSNRは差の大きさを示す指標で、知覚品質の評価ではありません。既定値を変える前に、
必ず映像そのものを確認してください。

初回はディスクからの読み込みが入ります。モデル読込の影響を除いて比べる場合は、2回実行してください。
現在のネイティブH3経路はジョブごとにモデルを読み直します。A100では生成本体が速くなるぶん、
この読込時間の比率が大きくなります。常駐ワーカー化は次の改善候補です。
